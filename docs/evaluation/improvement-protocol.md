# Bounded improvement protocol

The initial skill is Git commit `656dcc1`. Freeze its bundle and the supplied case, evaluator, model/backend, variant and timeout before changing runtime instructions. Use one revision per hypothesis, fresh workspaces, at most two candidate revisions and one replay per condition. Keep raw traces outside the repository and publish compact auditable summaries. This is a targeted engineering pilot with a fixed fixture and limited repeats.

## Trial I1 — Make experiment accounting visible at the point of action

The first Claude Code `algorithm/full` run issued three successful benchmark batches with a cap of two. Its report counted the baseline and candidate and then listed validation as an extra run. It also said it did not read the skill references. A failed compound Bash request was also visible. The coordinator had the accounting instructions only in supporting references.

Prediction: specifying the reservation and counting rule in the core prevents an extra measurement batch and causes a reader to use the experiment protocol. Keep the candidate if a fresh matched run has at most two measurement calls including any failed measurement dispatch, preserves the evaluator, and accurately reports the evidence and missing validation. If delegated work changes, distinguish this as a possible confound. A run that does no authorized measurement cannot by itself demonstrate better accounting.

## Trial I2 — Make a configured worker target operational

An explicitly configured count can read as a ceiling or target. Multiple initial runs can diagnose this using actual native traces. Candidate wording may be tested if agents omit requested roles even with native tools and enough time for small read-only assignments.

Prediction: with the count explicitly configured, a fresh Deep run launches four real distinct workers when available and records counts and any blockers accurately. Keep the candidate only if native traces show delivery or a specific truthful blocker, and a no-worker control remains useful. A requested and completed wave each need native evidence. Report any budget or endogenous routing change.

## Guardrails and stop

Keep Quick proportional. Preserve the no-objective/no-shell fallback and the baseline/evaluator constraints. Do not tune the benchmark cases to force a favorable response. Stop when two revisions are attempted, an independent check contradicts a change, the next evaluation would exceed the bounded pilot, or host quota blocks it.
