# Foundational evidence ledger

Reviewed 2026-11-24. Dates are publication, first preprint, or repository creation dates where labeled. Live specifications and docs are identified by review date. Publisher summaries, abstracts, historical scans, and project documentation have different evidentiary weight. Each row describes the scope of the source and the design inference drawn from it.

## Standards, harnesses, and deep research

| ID and source | Date and inspection | Finding | Limitation or conflict | Implication |
| --- | --- | --- | --- | --- |
| S01 [Agent Skills specification](https://agentskills.io/specification) | Live, specification | A named directory with YAML frontmatter and Markdown can load supporting files on demand. | File portability leaves tool availability, permission and orchestration semantics to the host. | Ship a standards-based bundle with capability negotiation. |
| S02 [Codex skill discovery](https://learn.chatgpt.com/docs/build-skills) | Live, official guide | Codex scans project and user `.agents/skills` paths. It exposes skill metadata for selection and supports explicit invocation. | Scope, duplicate names and trust affect discovery. | Document project and user paths and test with a clean project. |
| S03 [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) | Live, official guide | Native subagents support specialized tasks, model/effort settings and concurrency controls. | Tool surfaces and configuration aliases vary across versions. Settings and tools may be inherited. | Bind tools at runtime and request a fresh-context spawn where exposed. |
| S04 [Claude Code skills](https://code.claude.com/docs/en/skills) | Live, official guide | Skills can be discovered or invoked by slash command. `.claude/skills` is a native project path. | Forking a skill runs that skill in a separate agent context. It is not an orchestrator-worker protocol by itself. | Keep the orchestrator entry point portable and inline. |
| S05 [Claude Code subagents](https://code.claude.com/docs/en/sub-agents) | Live, official guide | Non-fork agents receive a fresh prompt. Forks share the parent transcript and may reuse cached context. Custom agents can specify model inheritance. | Fork defaults, agent wait behavior, tools and model availability vary by version and surface. | Choose fresh roles explicitly and report actual isolation. |
| S06 [MCP security guidance](https://modelcontextprotocol.io/specification/2025-11-25/basic/security_best_practices) | 2025-11-25 revision, specification | Tool interoperability still requires explicit client authorization and security boundaries. | Protocol connectivity provides neither independent assistants nor authority to trust retrieved content. | Keep tool transport optional and capability checks independent of provider. |
| S07 [OpenAI Deep Research launch](https://openai.com/index/introducing-deep-research/) | 2025-02-02, first-party report | Learned multi-step browsing can revise search plans and synthesize cited answers. | Internal comparisons and different model training confound architecture attribution. The report acknowledges hallucination and calibration issues. | Use adaptive retrieval and individually verify pivotal citations. |
| S08 [Anthropic multi-agent research system](https://www.anthropic.com/research/multi-agent-research-system) | 2025-06-13, engineering report | Orchestrator-worker architecture helped breadth-first tasks. The stated internal relative uplift was 90.2% for one specific model pairing. Multi-agent runs used about 15× chat tokens in their data. | Different models and token budgets prevent isolating the effect of orchestration. The 15× denominator is chat. | Delegate parallelizable branches, account for aggregate usage, and compare with a stronger single-agent control. |
| S09 [BrowseComp](https://openai.com/index/browsecomp/) | 2025-04-10, benchmark and paper | Persistent search and greater compute improved narrow, hard-to-find fact retrieval. Selection strategies benefited from additional samples. | Targeted training and short-answer tasks limit generalization. Even many attempts can miss a result. | Use search budgets with actionable stop criteria and separate retrieval from synthesis scoring. |
| S10 [DeepResearch Bench](https://arxiv.org/abs/2506.11763) | 2025-06-13, preprint | Evaluates reports with task-adaptive criteria and separately evaluates citation use and accuracy. | Reference and judge dependence can skew ratings. A good report can mask unaudited experimental claims. | Score citations and experiment validity separately from prose quality. |

## Scientific inference, evidence synthesis, and group behavior

| ID and source | Date and inspection | Finding | Limitation or conflict | Implication |
| --- | --- | --- | --- | --- |
| S11 [Chamberlin, Multiple Working Hypotheses](https://sciences.ucf.edu/biology/d4lab/wp-content/uploads/sites/23/2017/01/Chamberlin1890.pdf) | 1890, historical reprint | Multiple live explanations reduce commitment to a favored theory. | Methodological argument, with no comparative intervention study. | Include competing mechanisms and the null where meaningful. |
| S12 [Fisher, The Design of Experiments](https://wellcomecollection.org/works/zqfaugdd) and [NIST DOE handbook](https://www.itl.nist.gov/div898/handbook/pri/section3/pri33.htm) | 1935 historical catalogue and live handbook | Experimental design should match the comparison or screening objective. Blocking, randomization and replication address distinct threats. | Design options depend on feasible independent units and assumed interactions. | Define units, nuisance factors, order and repetitions in the protocol. |
| S13 [Box and Wilson, Experimental Attainment of Optimum Conditions](https://doi.org/10.1111/j.2517-6161.1951.tb00067.x) | 1951-01, publisher record and NIST discussion | Sequential response-surface designs offer an economical way to explore an unknown response. | Local surface assumptions can fail for discrete and discontinuous changes. | Prefer cheap screening and deliberate alternative branches over exhaustive sweeps. |
| S14 [Simon, A Behavioral Model of Rational Choice](https://doi.org/10.2307/1884852) | 1955-02, publisher record | Models decision processes under limited knowledge and computational capacity. | Theoretical model supplies no universal research budget. | Set practical adequacy and explicit stop rules before expanding work. |
| S15 [Lindley, Information Provided by an Experiment](https://doi.org/10.1214/aoms/1177728069) | 1956-12, paper abstract | Expected information depends on prior knowledge and the predicted observations. | Model-dependent. Reduction in uncertainty can be irrelevant to the action. | Use Bayes when defensible and rank tests by likely decision change per cost. |
| S16 [Wason, Failure to Eliminate Hypotheses](https://doi.org/10.1080/17470216008416717) | 1960-07, study | Participants often used confirming examples in a rule discovery task. | Narrow cognitive experiment. It does not quantify the bias of a host model. | Ask for a plausible counterexample and compare predictions before testing. |
| S17 [Platt, Strong Inference](https://bio.research.ucsc.edu/~barrylab/classes/bio183w/PlattSci1964_Strong_Inference.pdf) | 1964-10-16, paper scan | Explicit alternatives and discriminating experiments can focus inquiry. | Measurement failure and auxiliary assumptions can explain apparent falsification. | Preregister the observation that would weaken each claim and check test validity first. |
| S18 [Howard, Information Value Theory](https://ieeexplore.ieee.org/abstract/document/4082064/authors) | 1966-08, paper and abstract | The value of information depends on its effect on available decisions and their consequences. | Exact estimates require credible odds and utilities. | Use ordinal triage when exact inputs are unavailable. |
| S19 [Stasser and Titus, Pooling of Unshared Information](https://www.uni-muenster.de/imperia/md/content/psyifp/aeechterhoff/vorlesungkommunikation/stasser_titus_unsharedinfogroupdisc_jpsp1985.pdf) | 1985-06, paper scan | Discussion favors commonly held information and prior preferences. | Human hidden-profile tasks. Transfer to agents is an inference. | Collect unique evidence independently before exchange. |
| S20 [Lorenz et al., Social Influence and Crowd Wisdom](https://doi.org/10.1073/pnas.1008636108) | 2011-05, study | Social information reduced diversity without consistently improving collective accuracy. | Human numerical estimates, with experimental conditions unlike open-ended engineering. | Freeze initial memos and preserve evidence-backed dissent. |
| S21 [PRISMA 2020](https://www.bmj.com/content/372/bmj.n71) and [explanation](https://www.bmj.com/content/372/bmj.n160) | 2021-03, reporting standard | Record search, selection and synthesis methods and the basis of certainty judgments. | Reporting checklist is not a risk-of-bias tool or a guarantee of exhaustive retrieval. | Keep search and eligibility logs in deeper modes and avoid claims of systematic coverage without the protocol. |
| S22 [Kalibera and Jones, Rigorous Benchmarking in Reasonable Time](https://kar.kent.ac.uk/33611/) | 2013-06, corrected author manuscript | Repetition should target the levels where runtime variation arises. Report effect-size uncertainty. | Confidence intervals depend on sampling and comparability. | Use paired or blocked repeats, raw samples and practical thresholds. |

## LLM debate, memory, and resource trade-offs

| ID and source | Date and inspection | Finding | Limitation or conflict | Implication |
| --- | --- | --- | --- | --- |
| S23 [Du et al., Multiagent Debate](https://arxiv.org/abs/2305.14325) | 2023-05-23 preprint, ICML 2024 | Iterative exchange improved several tested reasoning and factuality tasks. | Specific models and tasks. Multiple generations and debate are distinct interventions. S24 and S25 find less general benefit. | Treat debate as a testable design choice and verify outcomes externally. |
| S24 [Smit et al., Should We Be Going MAD?](https://arxiv.org/abs/2311.17371) | 2023-11 preprint, ICML 2024 | Debate performance and cost depend on strategy and agreement behavior. Simpler methods are competitive. | Benchmark Q&A and tested debate topologies do not settle results for research with tools. | Use short disagreement-focused exchanges. Compare without debate. |
| S25 [Choi et al., Debate or Vote](https://arxiv.org/abs/2508.17536) | 2025-08 preprint, NeurIPS 2025 | Voting matched or beat debate in many tested settings. Their belief model predicts no gain from exchange alone under its assumptions. | New evidence and tool access can change the setting. Voting also fails under correlated error. | Exchange falsifiable objections and new evidence. Resolve on evidence quality. |
| S26 [Cemri et al., Why Do Multi-Agent LLM Systems Fail?](https://arxiv.org/abs/2503.13657) | 2025-03 preprint, NeurIPS 2025 | Trace taxonomy identifies specification, coordination and verification failures across seven frameworks. | Taxonomy reflects sampled frameworks and annotations. It does not estimate failure for this skill. | Give workers narrow assignments, verify deliverables and make result provenance auditable. |
| S27 [Sharma et al., Understanding Sycophancy](https://arxiv.org/abs/2310.13548) and [OpenAI rollback](https://openai.com/index/expanding-on-sycophancy/) | 2023-10 and 2025-05, study and incident report | Agreeable answers can be rewarded even when less truthful. A release was rolled back for increased sycophancy. | Assessed user/model responses and a first-party incident. Magnitude need not transfer to peer exchange. | Withhold lead preference and require observations that would change each view. |
| S28 [Bush, As We May Think](https://www.w3.org/History/1945/vbush/vbush8.shtml) and [Engelbart, Augmenting Human Intellect](https://www.dougengelbart.org/pubs/augment-3906.html) | 1945-07 and 1962-10, original texts | Persistent trails and structured records help people navigate earlier reasoning. | Conceptual precedents for people. They do not validate a particular agent memory format. | Use linked, compact, human-readable artifacts. |
| S29 [Liu et al., Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/) and [Anthropic context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) | 2024 and 2025-09, study and engineering guidance | Retrieval from long inputs is position-sensitive in tested models. Compact context and on-demand artifacts are practical design patterns. | Model/task effects vary. Removing context may remove decisive constraints. | Use compact role packets and durable evidence links with an explicit revision history. |
| S30 [Snell et al., Scaling LLM Test-Time Compute Optimally](https://arxiv.org/abs/2408.03314) | 2024-08 preprint, ICLR 2025 | The best use of test-time compute varies with problem difficulty and verification quality. | Math tasks and specific search and verifier settings. | Start with a cheap information-gaining step and escalate selectively. |

## Automated discovery, validation, and security

| ID and source | Date and inspection | Finding | Limitation or conflict | Implication |
| --- | --- | --- | --- | --- |
| S31 [King et al., Automation of Science](https://pubmed.ncbi.nlm.nih.gov/19342587/) | 2009-04-03, study abstract | Robot Scientist Adam linked formal hypotheses, recorded experiments and outcomes. | Domain-specific automation. It does not establish safety or transfer to open-ended work. | Preserve a trace from hypothesis to outcome, within the host's allowed scope. |
| S32 [Bergstra and Bengio, Random Search](https://www.jmlr.org/papers/v13/bergstra12a.html) and [Snoek et al., Practical Bayesian Optimization](https://arxiv.org/abs/1206.2944) | 2012, papers | Random search is a strong baseline when few dimensions matter. Bayesian optimization can allocate expensive evaluations using a learned response model. | Sample efficiency depends on noise, fit and search space. Small discrete searches seldom need a surrogate. | Use simple diverse search by default. Reserve Bayesian search for a justified measurable problem. |
| S33 [The AI Scientist](https://arxiv.org/abs/2408.06292) and [Sakana failure report](https://sakana.ai/ai-scientist/) | 2024-08, paper and engineering report | Automated idea-to-paper loops are feasible in constrained templates. Reported failures include unfair baselines and attempts to modify the execution timeout. | An automated review score cannot establish novelty or experimental validity. | Keep budget, evaluator and acceptance criteria under coordinator control. |
| S34 [AlphaEvolve](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/) | 2025-05-14, engineering report | Evolutionary search with objective evaluators produced reported mathematical and infrastructure improvements. | Evaluator-friendly tasks and substantial proprietary compute limit transfer. | Keep a small set of diverse candidates only where a trustworthy evaluation exists. |
| S35 [Karpathy, autoresearch](https://github.com/karpathy/autoresearch) and [program instructions](https://github.com/karpathy/autoresearch/blob/master/program.md) | Repository created 2026-03-06, implementation | Fixed five-minute training runs, small editable surface, results logging and keep/discard decisions make a simple feedback loop. | Hardware, task, and budget define the objective. Repeated optimization on a single metric can overfit it. | Adopt fixed envelopes, isolated changes, rollback, and fresh validation. |
| S36 [Dwork et al., Reusable Holdout](https://pubmed.ncbi.nlm.nih.gov/26250683/) and [Recht et al., ImageNet generalization](https://proceedings.mlr.press/v97/recht19a.html) | 2015-08 and 2019, papers | Adaptive reuse can compromise validity. Fresh samples can show shifts caused by difficulty as well as by selection. | Dwork's reusable holdout relies on a formal mechanism. A fresh-set drop alone does not diagnose overfitting. | Protect held-out cases and distinguish leakage, shift and noise. |
| S37 [Gao et al., Reward Model Overoptimization](https://proceedings.mlr.press/v202/gao23h.html) | 2023, paper | Stronger proxy optimization can degrade the underlying outcome. | Controlled synthetic oracle and proxy. The exact scaling curve does not transfer. | Freeze verifiers, use guardrails and check results outside the search proxy. |
| S38 [OpenAI, Testing Agent Skills Systematically](https://developers.openai.com/blog/eval-skills) and [WebArena](https://proceedings.iclr.cc/paper_files/paper/2024/file/4410c0711e9154a7a2d26f9b3816d1ef-Paper-Conference.pdf) | 2026-01 and 2024, guide and benchmark | Agent tests should verify observable outcomes, tool use and outputs under realistic tasks. | Sandbox and benchmark success predict only the measured behaviors. | Use real runs plus deterministic checks, with exact versions and capability records. |
| S39 [AgentDojo](https://arxiv.org/abs/2406.13352) | 2024-06, paper | A defensive evaluation found that untrusted tool outputs can interfere with task completion and steer agent action. | Benchmark scenarios and defenses do not guarantee safety for new tools. | Treat retrieved text as evidence and keep execution and external actions outside worker authority. |
